# Telegram audio transcriber bot

Бот принимает сообщения только в личном чате и доставляет результат в группу менеджеров. Голосовое сообщение копируется в группу с подписью, содержащей автора и транскрипцию. В личный чат бот ничего не отправляет. Сообщения, написанные непосредственно в группах, не транскрибируются.

По умолчанию используется `gpt-4o-mini-transcribe`. В официальной документации OpenAI endpoint `/v1/audio/transcriptions` поддерживает `gpt-4o-transcribe`, `gpt-4o-mini-transcribe`, `whisper-1` и `gpt-4o-transcribe-diarize`.

Второй этап на `gpt-5.6-luna` улучшает только пунктуацию, регистр, пробелы и абзацы. После ответа модели код локально проверяет, что все слова, числа и значимые символы остались в исходном порядке. Если проверка не проходит, редактура отбрасывается без повторного запроса. При низкой уверенности транскрибации второй этап не запускается.

## Быстрый старт

1. Создайте Telegram-бота через BotFather и получите `TELEGRAM_BOT_TOKEN`.
2. Получите `OPENAI_API_KEY` в OpenAI Platform.
3. Установите зависимости:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

4. Создайте `.env` рядом с `bot.py`:

```bash
copy .env.example .env
```

5. Заполните `TELEGRAM_BOT_TOKEN` и `OPENAI_API_KEY`. Сначала `MANAGER_CHAT_ID` можно оставить пустым.
6. Запустите:

```bash
python bot.py
```

7. Добавьте запущенного бота в группу менеджеров и разрешите ему отправлять сообщения.
8. Отправьте в группе `/chatid` (или `/chatid@имя_бота`), затем сохраните показанный отрицательный ID в `MANAGER_CHAT_ID` и перезапустите бота.

## Настройки

- `TRANSCRIBE_MODEL` - модель транскрибации. По умолчанию `gpt-4o-mini-transcribe`.
- `MANAGER_CHAT_ID` - ID группы менеджеров, куда пересылаются личные сообщения. Без него бот запускается для команды `/chatid`, но не пересылает и не обрабатывает личные сообщения.
- `TRANSCRIBE_LANGUAGE` - необязательная подсказка языка в формате ISO-639-1, например `ru`.
- `ENABLE_TEXT_CLEANUP` - включает второй этап редактуры. По умолчанию `true`.
- `TEXT_CLEANUP_MODEL` - текстовая модель второго этапа. По умолчанию `gpt-5.6-luna`.
- `SHOW_RAW_TRANSCRIPT` - добавляет исходную транскрипцию рядом с улучшенной, если обе версии помещаются в подпись Telegram. По умолчанию `true`.
- `ADMIN_USER_IDS` - необязательный список Telegram user ID через запятую. Если пусто, бот доступен всем, кто может ему написать.
- `MAX_FILE_MB` - лимит размера файла, не более 20 MB для обычного Telegram Bot API.
- `MIN_TRANSCRIPTION_CONFIDENCE` - порог предупреждения о низкой уверенности. По умолчанию `0.60`.
- `MAX_CONCURRENT_TRANSCRIPTIONS` - максимум одновременно обрабатываемых записей.
- `OPENAI_TIMEOUT_SECONDS` - тайм-аут запроса к OpenAI.
- `OPENAI_MAX_RETRIES` - автоматические повторы API-запросов. По умолчанию `0`, чтобы исключить дополнительную стоимость повторов.

Не указывайте `gpt-5.6-luna` в `TRANSCRIBE_MODEL`: endpoint транскрипции принимает только специализированные speech-to-text модели. `gpt-5.6-luna` используется отдельно в `TEXT_CLEANUP_MODEL`.

## Что поддерживается

- Доставка обычных сообщений из личного чата в группу менеджеров с указанием автора.
- Транскрибация личных Telegram voice messages с добавлением текста в подпись голосового.
- Транскрибация личных audio files и audio documents.
- Транскрибация личных video notes.
- Полное игнорирование обычных сообщений, отправленных непосредственно в группах.
- Отсутствие ответов, статусов и ошибок в личном чате пользователя.

Команда `/chatid` работает только в группе как служебный способ узнать её ID. Для каждого Telegram-токена должен работать только один экземпляр бота.

Telegram ограничивает подпись голосового сообщения 1024 символами. Если автор и транскрипция помещаются в этот лимит, в группе остаётся ровно одно сообщение: голосовое с полной транскрипцией. Для более длинного текста бот добавляет продолжение отдельным сообщением в той же группе, чтобы не обрезать данные. У video note нет поддержки подписи, поэтому его транскрипция также отправляется отдельным сообщением в группу.

Временные аудиофайлы удаляются после обработки.

## Защита от недостоверного текста

- Запрос выполняется с `temperature=0`, чтобы уменьшить случайность ответа.
- При доступных `logprobs` вычисляется геометрическое среднее вероятностей токенов. Это эвристика, а не гарантированный процент точности.
- При низкой уверенности менеджеры получают предупреждение и исходный текст; платный второй этап пропускается.
- Второму этапу разрешено менять только пунктуацию, регистр, пробелы и абзацы.
- Локальная проверка отклоняет результат, если изменилось хотя бы одно слово, число, значимый символ или их порядок.
- При принятой редактуре исходная транскрипция также добавляется в сообщение группы, если `SHOW_RAW_TRANSCRIPT=true` и хватает лимита подписи.
- Ошибки авторизации, лимита, тайм-аута, неверной модели и формата файла показываются отдельно.

Даже высокая уверенность модели не гарантирует дословную точность, особенно при шуме, нескольких говорящих, именах, номерах и профессиональных терминах. Для преимущественно русской речи можно установить `TRANSCRIBE_LANGUAGE=ru`; для смешанной речи лучше оставить значение пустым.

## Стоимость запросов

На одно сообщение выполняется не более двух платных API-запросов:

1. Один запрос на транскрибацию.
2. Один запрос на редактуру, только если она включена и уверенность транскрибации не ниже порога.

Получение `logprobs`, проверка слов и чисел, сравнение результатов и вывод исходного текста не создают дополнительных API-запросов. Повторной проверки другой моделью нет. При `OPENAI_MAX_RETRIES=0` SDK также не повторяет запрос автоматически.
